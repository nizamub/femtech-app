Product Overview 1.1 Vision FemHealth is an intelligent, adaptive symptom-assessment platform designed specifically for women's health. Patients answer a guided, decision-tree-driven questionnaire curated by registered medical experts. The system analyses responses in real-time, identifies probable health conditions, and delivers a personalised health report — all in English and Bengali. Experts manage the entire question library, condition logic, and analytics from a dedicated dashboard, with no developer involvement required. 1.2 Core Value Proposition Patients receive instant, evidence-informed health guidance from the comfort of their homes. Experts own and continuously improve the clinical content through a no-code dashboard. The system learns from aggregate anonymised data to surface population-level health trends. Fully localised in Bengali (বাংলা) so rural and semi-urban populations are not excluded. 1.3 Target Users User Type Description Primary Actions Patient / End User Women aged 9–65+, any literacy level, in Bangladesh and diaspora Take assessment, view results, download report, track history Medical Expert Registered doctors, nurses, health researchers Manage questions, define condition logic, view analytics, monitor patients Admin Platform superuser Approve experts, manage clinicians, system configuration 2. All routes support both locales. 4. Symptom Assessment Engine 4.1 Overview The assessment engine is a dynamic, branching decision tree driven entirely by expert-configured data stored in PostgreSQL. Questions are NOT hardcoded in the frontend. The engine renders the next question based on the patient's previous answer, following a logic graph defined by experts. 4.2 Core Concepts Concept Description Topic A clinical category (e.g. Fever, Menstrual Health, Thyroid). Each assessment begins with a primary topic selection. Question A clinical prompt belonging to a topic. Can be single-choice, multi-choice, scale, date, or free-text. Answer Option A selectable response. Each option carries a severity weight and can trigger a branch (next question override). Branch Logic An expert-defined rule: IF answer = X THEN go to question Y (or trigger condition Z directly). Condition A probable diagnosis (e.g. Malaria, PCOS, Dengue). Triggered when a scoring threshold or logic path is satisfied. Score Numerical weight accumulated per answer. Per-topic and overall scores determine condition probability. Assessment Session One complete run of the questionnaire by a patient. Stored in DB with all answers, scores, and conditions. 4.3 Complete Symptom Decision Tree — Initial Seed Data The following table defines the complete initial assessment tree to be seeded into the database by the engineering team. Experts will extend and modify this via the dashboard after launch. 4.3.1 Fever Module Question Type Options / Scale Branch Logic When did the fever start? Sessions HttpOnly, Secure, SameSite=Lax JWT cookies via Auth.js. Session expiry: 30 days. OTP 6-digit, 10-minute expiry, single-use, rate-limited: max 5 OTP requests per email per hour. API auth Every protected route validates session JWT and role. No security by obscurity. Input validation Zod schemas on all API routes and Server Actions. Reject unexpected fields. SQL injection Drizzle parameterised queries only. No raw SQL with user input. CSRF Handled natively by Next.js Server Actions. Security headers X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin, Content-Security-Policy. Security logging All auth events (login success/fail, register, OTP request, password reset) logged to security_logs table. Expert registration New expert accounts require admin approval before dashboard access is granted. Patient data Patient PII never returned in public or expert list API responses beyond what is necessary (no passwordHash, no raw OTPs). Rate limiting Upstash Redis rate limiting on /api/auth/* and /api/assessment/* routes (analytics: false). 12. Internationalisation (i18n) 12.1 Supported Locales English (en) — default locale. Bengali / Bangla (bn) — full translation required. 12.2 Implementation (next-intl) Route structure: /en/... and /bn/... — all user-facing pages nested under [lang] segment.
